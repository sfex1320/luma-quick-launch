# 双屏浮岛、通用快捷项与独立搜索

依据：用户本轮实测反馈。保留现有管理页风格、项目堆叠和 protocol=1，修复后发布到 APP/native/Luma。

## 已复现

- 原生日志证明展开后的旧 expanded=false 消息立即关闭窗口；React 被动 effect 中 MutationObserver 使用旧闭包。
- 两块屏幕只创建了主屏热区。
- 管理页两个菜单都指向 system；产品标题暴露“驾驶舱 · 原生内核”。
- schema 已支持 folder/file/app，但编辑器只提供选文件夹。搜索仅是管理页的已保存项目筛选。

## 实施与验收

1. 原生窗口：提交阶段同步布局，清理计时器；Hidden/AwaitingExpanded/Visible 握手。每屏热区、单个浮岛移动到触发屏，物理像素定位；全屏避让只作用对应屏。阴影区域保留但不出现全宽灰窗。验证反复唤出、双屏与负坐标。
2. 通用快捷项：单个入口也可独立置顶，组内可混合软件/文件/文件夹。原生选文件；拖放通过 WebView2 AdditionalObjects 获得真实路径，校验后保存，不自动打开。前端不发送任意执行命令。
3. 独立搜索：Ctrl+Alt+Space、托盘及浮岛搜索键打开独立窗口；Esc 关闭。搜索已保存入口、Windows 设置及 Windows Search 索引中的文件名/正文。标注索引范围和不可用状态，不后台扫描全盘。内核签发短期结果 ID，打开时再校验，前端不能传任意搜索路径启动。
4. 文案：保留一个“设置与备份”入口，移除产品界面调试标题；应用品牌始终 Luma。输入搜索不抢占管理页草稿。
5. 测试：前端构建/单元/E2E，原生单元与真实发布包集成。测试独立数据目录，用户配置不迁移、不覆盖。记录未验证环境边界。

## protocol=1 最小增补（不更改现有字段）

- `shell.pickFiles {}` → `{name,path,kind}[]`，取消返回空数组。
- `shell.resolveDrop {}` + AdditionalObjects File[] → `{name,path,kind}[]`。只有本次 WebView2 原生文件对象可提供路径，最多 100 个；纯 JSON 路径不接受。
- `search.query {query:string, scope:'all'|'shortcuts'|'files'|'content'|'settings'}` → `{results:[{id,title,subtitle,kind:'folder'|'file'|'app'|'setting',source:'shortcut'|'index'|'settings'}],indexAvailable:boolean,note:string}`，最多 60 条、输入 200 字符；空查询展示保存入口与设置。
- `search.open {resultId:string}` → `{accepted:boolean}`，ID 有界缓存 5 分钟，按客户端隔离；无效/过期返回错误。
- `window.closeSearch {}` → `{accepted:boolean}`。
- 现有 `window.openSettings {section:'search'}` 改为打开独立搜索窗；其他 section 不变。
