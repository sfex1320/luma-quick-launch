# 第二轮验收修复报告

日期：2026-09-19。交付目录：`APP/native/Luma/`。用户原配置保留，测试使用独立临时数据目录；最终已重新启动真实配置实例。

## 修复与新增

1. **顶部闪一下就消失**：旧 React MutationObserver 在提交后仍使用旧 visible=false，原生随即隐藏窗口。改为 useLayoutEffect，初始隐藏，每次宿主显示事件都重新上报布局，清理旧计时器；内核等待本次展开确认，防止旧消息和首帧回调重入撤销唤出。
2. **二次重入失效**：热区重排会取消驻留，但 HWND 仍记录鼠标在内；重排后按实际命中恢复一次驻留计时，没有新增空闲轮询。
3. **双屏**：各屏独立热区，共享一个浮岛窗口；使用物理坐标移动，支持左侧负坐标。全屏避让只针对所在显示器，排除桌面/任务栏。保留 180ms 悬停，增加单击顶边立即唤出。
4. **立体感**：增强浮岛投影，并为原生裁剪区域保留有限阴影边缘；仍禁止全宽 HWND 的 DWM system backdrop，避免原灰色大遮挡回归。
5. **通用快捷项**：软件、文档、文件夹可独立置顶或混合堆叠；编辑器提供类型选择。软件/文件多选保留 .lnk 本身及其参数；超出容量整批拒绝，不截断旧入口。
6. **拖入创建**：展开面板后，空白处创建独立快捷项，已有图标上加入堆叠。路径来自 WebView2 真实文件对象，普通消息空 AdditionalObjects 安全处理；保存不启动，重复路径去重。
7. **独立搜索**：Ctrl+Alt+Space、托盘、浮岛搜索键和 --search 打开独立窗口，Esc 关闭；管理页草稿不受影响。原生明确导航 /index.html，修复虚拟域根目录不能自动解析首页的问题。
8. **快速查询**：已保存入口、Windows 设置白名单、索引文件名和正文。文件名使用词首索引匹配，替代实测会超时的全名通配；正文使用 FREETEXT。连续输入保留每个客户端最后一个待查询请求，不丢最终关键词。最多一个索引工作线程，排队最多 2 秒、执行等待最多 4 秒。
9. **界面清理**：“内核状态”和“偏好与备份”原本指向同页，合并为“设置与备份”。移除“驾驶舱 · 原生内核”产品标题、避免品牌链接整页刷新；保留管理页原有布局风格。删除管理页状态灯的常驻动画，保留交互动效。

## 验证边界

- 双屏循环使用对实际 Win32 热区发送鼠标单击消息；它验证真实窗口路由、搬屏及布局，不等同于真实鼠标悬停循环。真实指针测试曾完成主屏多次及副屏唤出，但批量流程受 SetCursorPos 失败和其他桌面鼠标移动干扰，不能宣称完整六次物理悬停全部通过。保留 `node native/tests/native-smoke.mjs --pointer-hover` 供空闲桌面复验。
- 当前两屏缩放均为 150%，实际 WebView CSS 缩放约 189%（含系统文字缩放）；不同 DPI、显示器热拔插和全屏游戏未做真实硬件验收，已有坐标/状态单元覆盖。
- 拖放集成使用 Chromium Input.dispatchDragEvent 携带实际磁盘文件/目录，验证 WebView2 文件对象、原生路径解析、UI 保存及持久化；从资源管理器开始拖动到隐藏热区的完整 OLE 手势未验收。当前用法是先展开面板再拖入。
- 文件内容搜索只覆盖 Windows 已索引位置和支持的内容过滤器，没有修改系统索引设置或扫描全盘。文件名为分词词首匹配；纯标点或很大索引的查询仍可能超时，界面会说明。
- 原生磨砂当前为 WebView 玻璃视觉回退，不宣称已实现跨窗口的真实桌面背景模糊；不会用整窗背景重新造成灰色遮挡。
- 空闲性能采样使用 Measure-Idle.ps1，统计宿主及所有子进程；启动预热和打开管理/搜索窗口会增大内存。具体采样附后，不保证原始计划中的低内存目标。

## 最终静置采样

关掉管理/搜索窗、仅浮岛待唤出，预热后采样 8.57 秒：宿主及 6 个子进程共 **277 MB 私有内存**；CPU **0.55% 单核**，本机 24 逻辑核心折合约 **0.023% 整机**。DWM CPU 时间差与此前空载采样均为 0，精度内未测出增量；这不代表 GPU 占用或显存为零。本实现已低空闲 CPU，但 **内存仍有明显优化空间**，不能宣称小于 80 MB。完整数据见 idle-performance-round2.json。此前带管理页及动态状态灯的初步采样为 393.9 MB/22.92% 单核，场景不同，不作为严格 A/B 降幅。
