# 第四轮：自然滑入滑出、真实目录、图标成组

用户已明确要求修复并减少反复操作；本轮按已授权范围实施，不再要求批准已有交互决定。应用 systematic-debugging 与 subagent-driven-development：原生目录服务、动画、成组管理独立实现，主任务整合浮岛交互并验证。

## 已确认根因

- “电梯贴”保存为单个 folder 入口，实际磁盘中有两个子文件夹和一个文档。当前面板只渲染 project.items.slice(1)，没有目录枚举能力，不能将其误称为空目录。
- 第三轮替换了原 `.dock` 的 ease-out 进入效果，且每帧 window.sync 执行 WebView脚本、原生裁剪和日志。此次保留安全退出握手，但改为真实上下滑动；动画期间固定可覆盖路径的局部区域，避免逐帧改 HWND 区域。
- 现有卡片拖拽只是排序，浮岛无整理模式。需要明确提供图标合并与解组，保持名称、顺序与主入口规则一致。

## 用户行为

1. 普通单文件夹长按300ms/小箭头展开当前目录，展示实际一级子目录与文件；目录行可进入下一层，具有返回和打开当前目录动作。文件单击或长按滑选释放启动，移出取消；不能在按下瞬间启动。
2. 多入口组展示所有保存成员（包括第一个，默认单击仍打开第一入口）；目录成员可继续浏览其内容。目录内容只按需读取，不保存成快捷项，不做递归或常驻扫描。
3. 浮岛右侧“整理图标”切换编辑模式。此模式图标可拖到另一图标合并。目标组保留名称、颜色和原成员顺序，来源成员追加，路径去重；合并完成移除来源图标。组内“拆成独立图标”恢复独立入口，文件从不移动。非整理模式维持长按滑选，不混用拖拽成组与启动手势。
4. 图标组合显示最多四个小图标及数量，软件组不能全部伪装成文件夹；单目录继续水晶文件夹。设置页提供组合/拆分入口，原有拖动手柄排序保留。
5. 动效仅纵向平移与适度淡入淡出、不缩放弹跳；展开约360ms、回收约300ms，原生退出800ms兜底及visibilityId继续保留。交互反向从当前画面开始，减少动态效果仍直接切换。

## protocol=1 最小新增（先记录再实现）

`folder.list {projectId,itemId,folderId?:string}` → `{folderId,name,entries:[{id,name,kind:'folder'|'file'|'app'}],parentId:string|null,truncated:boolean}`。

`folder.open {projectId,itemId,entryId:string}` → `{accepted:boolean}`。

初次list省略folderId，根必须是仍然保存的folder入口。后续 folderId/entryId 仅由宿主签发并按clientId、projectId/itemId、当前根路径隔离，5分钟过期；打开前重验当前根、存在性、边界，不接受前端原始路径。folderId本身也可用于打开当前目录。枚举限当前层200项（超过明确提示），有界后台并发/超时；权限或目录变化明确报错，链接/重解析点不隐式越过绑定根。无递归扫描、保存或启动副作用。
