# Luma 前端设计与实现规范

状态：前端及原生联调第二轮。管理页使用当前驾驶舱布局；新增通用快捷项、双屏浮岛和独立搜索，详见《第二轮验收修复报告》。

## 架构决定

前端采用 React + TypeScript + Vite，图标使用 lucide-react 与自制 CSS 水晶文件夹。没有外部字体、图床、动画引擎或网络素材依赖。原计划的纯 WPF UI 路线调整为“现有 Web 前端 + Windows WebView2 宿主”；建议内核用 C# 构建窗口和系统服务，但不让内核重写前端。

这项调整服务于已确定的前端分工。它不意味着已证明 WebView2 达到原计划内存目标；内核联调后应测整个进程树，按实际结果优化。

## 页面与运行方式

- `/`：项目与外观管理工作台。左侧导航、中部真实交互预览与项目卡片、右侧外观调节。
- `/?view=dock`：只有浮岛与展开堆叠的透明页面，用于独立浏览器预览。
- `/?view=dock&mode=native`：原生浮岛，必须有 WebView2 桥。
- `/?mode=native&section=appearance`：原生外观管理。
- `/?view=search&mode=native`：独立原生搜索面板；宿主虚拟域使用 `/index.html?view=search&mode=native`，不能假设目录根自动解析首页。
- 任意页面发现 `window.chrome.webview` 就进入原生模式。原生连接失败必须显示失败，不能装载示例状态。

## 视觉

默认名 Luma，鼠尾草绿与暖灰底色，深绿色操作按钮。项目颜色 mint、blue、violet、peach、gold。水晶文件夹用静态渐变、倒角高光、纸张和最多三层轮廓呈现；不导入需要 GPU 常驻运行的 3D 场景。

面板：默认 640 × 88 CSS px；在 WebView2 默认缩放下视为 DIP。圆角 22，图标 40。宽 320–1120、高 64–160、图标 24–64、圆角 12–32。不足时由 `src/core/layout.ts` 计算有效值，偏好仍原样保存。

第十二轮标签规则：一级浮岛的文件夹、软件与集合统一使用 12px、400 字重、18px 行高；标签尺寸不随图标种类或图标大小变化。图标放在统一的正方形行中，标签使用独立且不可压缩的 18px 行，间距 4px，避免文件夹图形比软件图标矮而改变标签基线。长名称只在水平方向省略，文字上下不得裁切。浮岛垂直内边距 4px，滚动轨道不重复增加垂直内边距，为窄屏横向滚动条保留空间；玻璃材质与 650ms 推出 / 600ms 收回不变。

系统页卡片底部的“查看操作指南”与卡片内容统一保持 14px 左右内缩及 14px 底部间距，不贴卡片边框。

三个材质值：frost 强磨砂、soft 轻透、solid 实色。网页 CSS 只能模糊本页面内容；透出其他应用的磨砂来自原生宿主。不可宣称网页 backdrop-filter 已完成 Windows 桌面磨砂。

浅色与深色都已实现。减少动效设置和系统 prefers-reduced-motion 同时生效。图标不在空闲时循环发光、旋转或弹跳。

## 已实现交互

- 短按在 pointerup 请求主目录。
- 连续按住 300 ms 展开同项目入口，滑到目录后松手只请求该目录一次；长按后原地松手保留面板。
- 长按前移动超过 6 px 取消候选；浮层外松手、pointercancel、窗口失焦或失去捕获取消手势。
- 小箭头、右键和键盘 ArrowDown 提供展开替代路径；Esc 先关闭堆叠，再隐藏快捷栏。
- 预览热区驻留 180 ms 展开；离开快捷栏且无堆叠/菜单时 650 ms 收起。系统屏幕顶边的唤出由宿主负责。
- 常用目录使用固定顺序的紧凑列表；超过 6 个其他入口时改双列网格。此版以稳定可选区替代斜向扇形，避免文字旋转与重叠。
- 新建/修改项目与文件夹、颜色、置顶、前后排序、移除入口、搜索、配置导入导出、外观预设/滑块、重置与撤销调整。
- UI 中的“最近”“同步账号”“AI 分类”等未实现能力没有伪造开关。

## 自适应

`computeLayout(width, height, icon, viewport, textScale)` 保持图标宽高比并预留文字空间；一级浮岛标签按上述固定字号规则显示。入口超过屏幕容量时使用横向滚动。浏览器/WebView 原生缩放负责 CSS 到物理像素转换，不可再由宿主把 JSON 尺寸重复乘两次 DPI。

工作台在窄屏将侧栏收为图标、外观面板下移，项目卡片由三列变两列/单列。工作台的辅助注释字号与 Dock 字号分开管理。`textScale` 的单元测试验证文字放大下的最小空间；真实 Windows 系统文字缩放需要内核联调，尚未宣称完成。

## 后续扩展边界

第十二轮目录操作：打开当前目录、测试软件/打开项目软件、新建文件夹、复制地址共用同一条底部工具行，统一30px按钮高度、10px文字和13px图标，不换行；窄屏在该行内横向滚动，不挤压上方文件格子。实际移动使用同行小图标专用落点，确认表单仅在明确操作后出现。命令详情放启动按钮title，不再常驻命令、计数、滑选说明和大块移动备注。所有底部操作均支持点击、键盘，以及已长按状态滑入松手；新建只打开命名确认表单，不直接写磁盘。移出取消、禁用按钮不执行、布局位移不误选保持不变。

第六轮补充：深色模式显式控制网页滚动条和滑块配色；原生设置/搜索窗口同步标题栏与WebView配色。外观行为设置（自动收起/减少动效、说明、撤销）使用统一14px卡片内边距。窗口恢复与复用由宿主共同启动出口负责，前端保持现有ID/令牌请求，不用页面标题判断软件是否已开。

第五轮增补优先于下文历史范围：已实现真实一级目录浏览与引用成组。当前推拉为650ms推出/600ms收回、完整纵向位移、透明度恒1；右侧固定搜索/编辑/设置，二级菜单88×94固定格子，打开当前目录支持长按滑入松手。软件原图标保留品牌内容并加圆角玻璃底座、高光和阴影，失败回退通用图标。具体边界和实测见《第五轮修复报告.md》及协议文末。

第三轮增补优先于下文历史范围：设置页支持外部文件拖入空白/卡片/编辑表单，卡片手柄支持排序。原生路径仅来自 WebView AdditionalObjects，经校验后由前端原有 CAS 保存。浮岛保留退出 DOM 至动画结束，通过可选 window.sync.interacting 显式报告操作状态。详细语义见《内核接口协议》；未添加目录扫描和缩略图。

本轮未实现跨项目拖拽整理、文件系统实时目录浏览、路径修复向导、已开窗口定位、自动开机启动和多屏系统 UI。不要以这些未来功能为由重构已完成的视觉与数据模型。原生拖入路径可由后端完成归组后广播新状态，前端自动更新；行为需要额外验收。

## 第十三轮交互补充

子菜单的空白区域采用左键抓手：静止grab，按下移动达到7px后grabbing，上下拖动内容；图标、按钮、表单和可拖动引用不作为抓手起点。主面板保留右键左右拖动。含软件的多入口组在悬停时只有一个占满图标的“进入”，快速点击亦进入；单软件仍打开软件/最近，目录仍打开/进入。移除右上角独立下拉角标，编辑X与移出保留。

设置与备份包含“快捷键”卡片，继承当前主题和20px内容内边距；录制按键后显示组合、范围和真实注册状态。单键固定面板内，组合键可全局；占用/目标失效必须显示。全局组合键在录制期间暂停并在结束刷新状态；无焦点、表单输入或对话框期间不触发面板快捷键。
# 第十四轮增补（2026-09-22）

- 收藏星仅整理模式显示（主栏17px，子菜单23px点击区），普通模式不显示收藏按钮，不恢复下拉箭头。星标按下不得传入打开、长按或真实目录拖动；仅改变引用。
- 收藏在主栏同一横向滚动轨中分区，有可辨分割线及略深同材质底框。额外间距计入自动宽度，1120px/屏幕宽度上限保持。收藏匹配索引随项目数据变化更新，不随每次指针移动重复扫描全部收藏。
- 目录标准4列×2整行，格子88×94px，内容区218px；窄屏保留固定格子并缩减列数，可滚动。根目录重复标题行删除，最深目录刷新在标题栏关闭按钮前，深层必要名称/返回保留。
- 打开目录、打开项目软件、新建文件夹、复制地址仍同排。末尾箭头是实际目录移动入口，空待移动状态点击说明用途，已有待移动项则打开确认表单；不能无反馈，也不能变成不经确认的磁盘移动。
- 成功打开后滑入收起，自动收起/再次展开保留浏览位置；记忆只保留本次运行，重新读取目录并处理失效路径。减少误触不能改成短时淡出或弹跳。

## 图标按钮与角标几何（2026-09-23 起）

- **所有仅含图标的按钮必须显式声明 `padding:0`**。Chromium  UA 默认给 `<button>` 加 `padding:1px 6px`：对称时看似无害，一旦内容盒比图标窄，CSS 盒对齐的"安全溢出"规则会把 `place-items:center` 退化为起始对齐，图标被顶偏（收藏星、移除叉都踩过）。涉及 `.favorite-button`、`.shortcut-remove`、`.shortcut-extract`、`.icon-button`、`.shortcut-badge` 等。回归断言见 `tests/sixteenth-panel.spec.ts`（字形与按钮中心偏差 < 0.5px）。
- 编辑模式磁贴角标布局固定：左上=移除快捷引用（X）、左下=移到主面板（↗）、右上=收藏（☆）、右下=快捷键徽标（只读小字，pointer-events:none）。快捷键徽标格式：修饰键缩写 C/S/A（Ctrl/Shift/Alt）+ 主键字符，如 `CB`=Ctrl+B、`CSAC`=Ctrl+Shift+Alt+C。
- 材质三档必须同时覆盖主栏、堆叠面板、更多面板、二级及以下所有子菜单列，且明暗两主题都定义；`.glass` 只承载默认磨砂基调，禁止用更高优先级的面类选择器覆盖材质类（`.overlay-dock .glass` 曾覆盖 `.material-*` 导致子菜单失效）。实色=微透（约 95% 不透明）且 backdrop-filter:none；强磨砂=blur(28px) saturate(140%) + 可辨识颗粒纹理（data-uri feTurbulence，不增加命中区域）。
- 动效由 `useDockMotion` 的独立主栏/子菜单 WAAPI 动画驱动，`preferences.motionSpeed`（relaxed/standard/brisk）三档主栏为650/600、520/450、380/320ms，子菜单为200/160/120ms。弹出为一级先完成、二级随后更快完成；收起为二级先完成、一级随后完成。已展开状态切换组或文件夹直接换内容，不重新播放子菜单滑动；目录加载中保留218px网格+45px动作行的空间（短视口仍可收缩），避免先塌缩再撑开。二级以一级下边界裁剪，不叠加主栏位移，也不淡出。反转读取当前实际变换；两层都完成才提交 collapsed。window.sync 扣除各自的位移，保留静止区域及扫过区域至收回完成；禁止逐帧 window.sync/SetWindowRgn。拆分层级后必须保留 `.dock-stage .stack-panel` 的 flex 布局和短视口约束；裁剪层不得引入页面滚动条。
## 第二十三轮：子菜单文字与软件能力

- 子菜单项目标题与当前目录标题统一 12px / 18px；入口计数使用独立 `.stack-entry-count`，11px / 18px、单行、不可收缩，不依赖 `:last-child` 等子节点位置。
- 软件、目录和最近项目名称均为单行省略号，不使用两行 line-clamp。名称或对应按钮保留完整 `title`；最近项目路径同样单行省略，并保留完整提示。
- 二级顶栏的标题、筛选框和当前目录名可收缩，所有相关 flex 容器/文字子项设 `min-width:0`；计数、返回、刷新、关闭按钮保留宽度。约 402 CSS px 面板及高 DPR、文字缩放环境下不得将计数挤成竖排或推出控制按钮。
- 软件的最近项目入口以宿主 `shell.getAppCapabilities` 返回的 `recentSupported` 为准；未知、失败或不支持时只有“打开软件”，图标使用 `AppWindow`。悬停、长按、方向键与上下文菜单遵守同一能力判定。多软件分组仍可进入组菜单。
- 能力请求只传保存的 projectId / itemId；前端缓存身份包含保存路径与提交代次，最多 4 个并发、256 个缓存/排队条目。保存后失效，旧响应不得重新启用新身份；不为探测能力读取最近列表，不添加常驻轮询。

### 文件拖放

- 普通模式拖动真实文件或保存入口：默认/Ctrl=复制、Shift=移动、Alt=创建快捷方式；Alt 优先于 Shift。悬停提示和确认标题显示当前动作，快捷方式不得称作“快捷键”。
- 主栏及组内文件夹磁贴接收至该根目录；目录磁贴接收至该子目录，目录列空白接收至当前列。组有多个目录或主栏空白时列出目标选择，不猜测默认目录。落在软件上不能将文件塞入软件安装目录。
- 编辑模式拖放只操作快捷引用，不触碰真实源文件。普通模式主栏入口拖到另一文件夹是文件操作，不隐式合并组。
- 确认面板明确显示动作、来源和目标，提交中禁重复提交、持续保持交互和最终响应；同名冲突必须可见，部分成功不能显示为全部成功。确认面板必须显式恢复 pointer-events，实际操作完成后重新获取目录令牌。
