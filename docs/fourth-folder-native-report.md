# 第四轮原生目录服务与桥接验证

日期：2026-09-19。范围：`FolderService.cs`、`BridgeRouter.cs` 和对应原生单元测试。未发布、重启宿主或启动用户文件，未修改用户配置。

## 根因与修复

原生没有 `folder.list` / `folder.open` 路由。使用临时目录“电梯贴”（两个子目录和一个 PPTX）的桥接回归用例首先失败，响应为 `METHOD_NOT_FOUND`；实现后返回真实一级子项，文件夹优先并按 Windows 自然名称排序。

`folder.list {projectId,itemId,folderId?}` 与 `folder.open {projectId,itemId,entryId}` 保持 protocol=1 和已记录的第四轮字段语义。首次从最新保存状态解析 folder 入口；后续仅接受宿主签发的随机令牌。令牌绑定 clientId、projectId、itemId、规范化根路径和子项路径，五分钟到期。返回当前目录令牌、可用父目录令牌和最多 200 条子项；读取第 201 条即停止并设置 truncated。只按需列当前层，不读取正文、递归扫描、保存目录内容或在列举时启动。

打开时再次验证最新保存根、存在性、文件/目录类型及路径边界，然后通过现有 `IShellExecutor` / Windows Shell 启动。同一 clientId + requestId 在一分钟内共享一次结果，进行中的重复请求不会重复启动。测试注入 FakeShell，未调用实际 Shell。

所有路径组件（包括保存根的祖先）拒绝重解析点；列举前后都检查，打开前重新检查。目录内 `.lnk` / `.url` 可显示，但拒绝隐式跟随，中文提示将真实目标另存为入口。该保守策略也会阻止安全的目录联接点；本轮没有实现链接目标解析。

## 资源边界与错误

- 全宿主最多两个目录后台操作；四秒响应超时后，真实 I/O 未结束则继续占用原有工作槽，后续返回 BUSY，不堆积遗留网络任务。
- 最多 4096 个目录令牌；签发前为当前完整页面预留容量，淘汰旧页不会立即使当前响应失效。
- 最多 512 个一分钟打开请求去重记录；满额返回 BUSY，不淘汰仍需保证幂等性的记录。
- 无权限、路径删除、非目录、令牌失效和 I/O 超时均返回对应协议错误与中文说明，不向前端暴露原始异常或磁盘路径。

## 动画确认时序补充

按主任务要求，将 `window.sync` 的 `applied:true` 应答放到 `_sync.Post` 回调中，在 `SyncDock` 返回后发送。回调失败也返回一次错误。新增延迟调度测试确认：宿主尚未执行更新时没有成功应答。这不更改 visibilityId 或最终 collapsed 隐藏规则。

## 自审结论与验证范围

自审修复两个额外问题：盘符根路径不能重复拼接分隔符；目录在枚举期间变为重解析点时，必须在返回内容前再次拒绝。两者都观察到对应回归用例失败后再修复并全量验证。

本报告证明原生服务/桥接代码及 Windows 文件系统临时目录单测通过，不构成真实运行宿主的 WebView2 交互验收。主任务发布原生改动后仍需运行 `npm run test:native`，并验收真实浮岛目录浏览与动画。Windows Shell 按路径启动仍存在文件系统外部并发修改的常规检查/使用间隔；本服务在列举前后、启动前重验，未声称提供跨进程文件系统事务。
