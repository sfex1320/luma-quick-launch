# Luma 原生内核接口协议 v1

第十二轮补充（优先于历史开发启动离线限制）：自动识别test/cargo test等测试入口继续已有子进程离线策略；明确Tauri dev/dev/start的“打开项目软件”属于开发入口，与已保存手动命令一样沿用用户环境，不再强制CARGO_NET_OFFLINE/COREPACK等覆盖。识别和保存不执行；仅用户点击才执行已展示项目命令，项目自己的开发脚本可能按原配置获取依赖，宿主不另行执行install/fetch，也不清除用户主动设置的offline值。同指纹重新识别时刷新既有taskId有效期，但点击仍重新核对清单指纹。protocol和JSON字段不变。

第十二轮软件最近来源：shell.getRecent生产实现读取Photoshop/Illustrator/InDesign各自Adobe MediaBrowser MRU，核对exe公司、产品、原始文件名以合理归属（不是签名认证）；逐键最多256次，注册表字符串先限类型/字节再分配。按应用支持格式、存在的普通文件、时间排序去重及6–10条返回，打开前重验身份与令牌。其他软件无可靠独立来源时返回空和说明，不用全局WindowsRecent同扩展名样本冒充。样本可能遗漏最新记录；无后台扫描、无写用户历史。

此文档与 `src/contracts.ts` 一起构成实现约束。不要重新命名字段、创建第二套桥接协议或把前端改为原生控件。所有 JSON 字段采用 camelCase。

## 1. 传输

前端通过 `window.chrome.webview.postMessage(object)` 发送请求。宿主监听 WebMessageReceived，用 PostWebMessageAsJson 回应；前端只监听 `window.chrome.webview` 的 message 事件，不使用可被任意 iframe 发送的全局 window message。

宿主将 `dist/` 映射到 `https://luma.local/`，只允许本地可信顶层页面发消息；拒绝其他来源、非顶层文档和未经允许的页面导航。导出下载仅处理本应用产生的 blob 内容；导入文件由用户选择，不自动执行。

```json
{"protocol":1,"type":"request","id":"UUID","method":"app.getState","params":{}}
```

成功：

```json
{"protocol":1,"type":"response","id":"相同的UUID","ok":true,"result":{"schemaVersion":1,"revision":0,"projects":[],"preferences":{"width":640,"height":88,"iconSize":40,"radius":22,"material":"frost","theme":"light","reducedMotion":false,"autoHide":true}}}
```

失败：

```json
{"protocol":1,"type":"response","id":"相同的UUID","ok":false,"error":{"code":"PATH_NOT_FOUND","message":"文件夹已移动，请重新设置路径。"}}
```

每个请求恰好一个应答；响应顺序可不同，以 id 关联。普通请求前端超时 8 秒；选择目录对话框超时 120 秒。耗时文件访问必须在后台执行，不阻塞 UI。超时不自动重试启动请求。

错误码固定集合：INVALID_REQUEST、UNSUPPORTED_PROTOCOL、METHOD_NOT_FOUND、REVISION_CONFLICT、PATH_NOT_FOUND、ACCESS_DENIED、IO_ERROR、CANCELLED、BUSY、INTERNAL_ERROR。message 为可读中文，不暴露堆栈和敏感环境信息。路径不存在等错误不要返回 ok=true。

## 2. 数据模型

机器可读契约：`docs/contracts/state.schema.json`、`results.schema.json`。由 `node scripts/generate-contract.mjs` 从前端 schema 生成；不要手工修改。ID 唯一性另由业务验证（JSON Schema 不能表达按 id 唯一）。

| 对象 | 字段 | 语义 |
|---|---|---|
| AppState | schemaVersion=1、revision、projects、preferences | revision 为单调递增非负整数 |
| Project | id、name、description、color、pinned、items | id 稳定；项目名 1–60 字；最多 100 个项目 |
| LaunchItem | id、name、path、kind | 每项目 1–200 项；item[0] 是单击入口；kind 为 folder/file/app |
| Preferences | width、height、iconSize、radius、material、theme、reducedMotion、autoHide | 范围与枚举见 schema；存用户偏好，不存临时布局结果 |

项目 ID 在状态内唯一；item ID 在该项目内唯一。初始空状态用 `empty-state.json`。不得把浏览器演示路径作为新安装用户的数据。

路径与名称分别验证。Windows 路径接受本地绝对路径、UNC 路径；拒绝内嵌 NUL、非文件 URL 和任意命令串。快捷方式作为文件启动由 Shell 解释，程序启动不走 cmd /c 或 PowerShell 字符串拼接。协议 v1 不支持任意启动参数；需要带参数应用时由用户使用 .lnk，或未来显式升级契约。

## 3. 基础六个方法（新增能力见文末增补）

### app.getState

- params：`{}`。
- result：完整 AppState。
- 启动时读取 `%LOCALAPPDATA%/Luma/state.json`；主文件损坏尝试有效备份，均损坏则返回 IO_ERROR，不静默丢失用户数据。
- 新安装不存在配置时返回 empty-state，不先创建示例项目。

### app.saveState

- params：`{"state":AppState,"expectedRevision":整数}`。
- result：持久化完成后的 AppState，revision=旧 revision+1。
- 在同一把锁内检查 expectedRevision、验证 schema 和 ID 唯一性、写临时文件、替换主文件、保留有效备份。不要在写完磁盘前返回成功。
- 过期版本返回 REVISION_CONFLICT，不覆盖；state.revision 必须等于 expectedRevision。
- 保存完成后仅向其他管理/浮岛页面发 app.stateChanged；请求来源页面通过 response 收到结果，不再回声广播给来源，避免其未保存的新编辑被误判为外部变更。
- 保存行为不得打开目录或应用。

### shell.openItem

- params：`{"projectId":"atelier","itemId":"design"}`。
- result：`{"accepted":true}`，表示操作系统接受启动请求，并不表示外部软件已经完全启动。
- 根据最新已保存状态解析 ID 和真实路径，校验存在/可访问后调用 Shell。
- 同一请求 id 在当前进程内至少缓存 60 秒处理结果，重复消息返回原结果，不重复启动。
- 不按文件夹标题猜测已打开窗口；当前窗口复用规则见文末第六轮增补。

### shell.pickFolder

- params：`{}`。
- result：`{"path":"D:\\Projects\\Example","name":"Example"}`；用户取消返回 `null`。
- 使用系统文件夹选择对话框，归属设置窗口，在对话框结束前保持该窗口可操作。

### window.sync

- params：`{"expanded":true,"rects":[{"x":20,"y":16,"width":640,"height":88}]}`。
- result：`{"applied":true}`。
- rects 是 **当前浮岛 WebView 客户区内的 CSS px**，不是屏幕坐标，不是物理像素。宿主按 WebView 实际 devicePixelRatio 转换一次；它包含显示缩放、系统文字缩放和页面缩放，不能直接使用 WPF DPI。实测显示缩放 150% + 文字缩放 126% 对应 1.89 物理像素/CSS px。
- expanded 表示主快捷栏可见，未展开时仍有热区矩形。展开堆叠时矩形集合包含主栏与堆叠/更多面板；可见操作反馈 toast 也属于可交互矩形，不能被窗口裁剪掉。
- 宿主在这些可交互区域及窄连接通道内接收鼠标，其他透明区域穿透；不允许整个屏幕宽度拦截鼠标。
- 客户区要预留展开堆叠的高度：默认选定显示屏工作区宽度、至多 640 DIP 高的透明渲染区域，再按 rects 限制输入和材质范围。这里只扩大透明承载区，实际面板仍由前端宽度控制，不能铺满视觉面板。
- 热区与面板之间的留白属于连续交互通道，不能在光标经过通道时收起。前端布局变化时会同步，宿主不得为每帧请求重建窗口。
- 浮岛背景原生 Acrylic 需裁剪到真实面板区域，不能把整个透明承载区磨砂化。先验证宿主实现；有平台限制时使用带相同视觉层次的实色回退并记录限制。

### window.openSettings

- params：`{"section":"appearance"}`，section 仅为 projects / appearance / search。
- result：`{"accepted":true}`。
- 打开或激活单个管理窗口，URL `/?mode=native&section=对应值`。管理窗口可接受键盘焦点。
- 浮岛内搜索和设置交给管理窗口，避免在有限浮岛命中区域内弹出大对话框。

## 4. 宿主主动事件

```json
{"protocol":1,"type":"event","event":"app.stateChanged","data":{"schemaVersion":1,"revision":3,"projects":[],"preferences":{"width":640,"height":88,"iconSize":40,"radius":22,"material":"frost","theme":"light","reducedMotion":false,"autoHide":true}}}
```

```json
{"protocol":1,"type":"event","event":"window.visibility","data":{"visible":true}}
```

只发送这两种已定义事件。前端忽略无效事件、旧 revision 和未知请求 ID。外部状态与未保存本地编辑冲突时前端会停止写入并要求重新载入，不擅自覆盖。

宿主检测顶边驻留后发送 visible=true；游戏/视频全屏避让、显示器切换等需要隐藏时发送 false。悬停展示不要自动夺走原应用焦点。托盘明确唤出管理界面时可激活焦点。

## 5. 资源和生命周期

- 两种窗口共用一个后端 StateStore。管理窗关闭后释放它的 UI 资源，常驻只保留必要浮岛和事件监听。
- Windows WebView2 的 DefaultBackgroundColor 必须透明；HTML 的背景已为 dock 视图透明。
- OS 透明效果关闭、远程桌面或性能档位选择实色时，宿主同步正确材质回退，不保留无效模糊绘制。
- DPI、显示屏改变先取消进行中的手势：发送 visible=false，更新窗口，再发送 true。不要在指针按住时搬动选项。
- 删除入口只更改配置，不删除真实文件。退出不能丢掉已回应成功的配置。

## 2026-09-19 用户验收后的兼容增补

背景和边界见 `2026-09-19-可用性修复计划.md`。protocol=1、状态 schemaVersion=1、已有 JSON 字段、保存的乐观并发及两个事件均不变。项目可含一个独立快捷项，或多个软件/文件夹/文档组成堆叠，不要求每个入口属于工程项目。

| 新方法 | params | result |
|---|---|---|
| shell.pickFiles | `{}` | `{name,path,kind}[]`；取消为 `[]` |
| shell.resolveDrop | `{}`，同时带 WebView2 AdditionalObjects File[] | `{name,path,kind}[]` |
| search.query | `{query,scope}` | `{results,indexAvailable,note}` |
| search.open | `{resultId}` | `{accepted}` |
| window.closeSearch | `{}` | `{accepted}` |

- 文件选择器保留 .lnk 本身（DereferenceLinks=false），不解析成丢失参数的目标路径。对话框超时 120 秒。
- 拖入路径只能从本条 WebMessage 的 CoreWebView2File.Path 取得。普通 postMessage 的 AdditionalObjects 可为 null；必须空值兼容。拒绝纯 JSON 伪造 paths。最多 100 项，整批校验后交给前端，通过原有 app.saveState 保存；选择/拖放不启动。
- search.query 的 scope 为 all/shortcuts/files/content/settings，query 最多 200 字符。每条结果 `{id,title,subtitle,kind,source}`；kind 为 folder/file/app/setting，source 为 shortcut/index/settings；最多 60 条。
- 文件名使用 Windows 索引的分词词首匹配；正文使用 FREETEXT；不扫描全盘。indexAvailable 只表示本次实际索引查询是否成功；空查询/仅快捷项或设置范围为 false，note 解释原因。不得把索引未覆盖或查询失败说成全磁盘没有结果。
- 搜索打开只接受内核签发的短期 ID，按 clientId 隔离、5 分钟有效；保存入口仍用最新 projectId/itemId 解析，索引路径启动前重验，设置 URI 只能来自原生白名单。前端不能提供 URI 或任意路径作为 search.open 参数。
- `window.openSettings {section:'search'}` 现在打开独立搜索窗口，不导航管理页、不损坏草稿。系统级 Ctrl+Alt+Space、托盘“搜索”及 --search 都可唤起。被其他程序占用时快捷键注册失败写日志，托盘入口仍可用。
- 原生浮岛初始 visible=false。每次 window.visibility 事件都强制重新提交布局，即使布尔值不变；观察 DOM 的 effect 必须在 React 提交阶段清理旧观察器。宿主等待展开确认后才显示，初始 LayoutReady 的同一调用栈不能确认它新触发的唤出。
- 第三轮最小增补：`window.sync.params.interacting?: boolean`，省略按 false 解释。按压、拖入、等待导入、键盘操作和打开堆叠期间前端报告 true，供原生延缓自动回收；不以矩形数量推断交互。退出请求发出后该标记为 false。
- 可见性编号：`window.visibility.data.visibilityId?: number` 与 `window.sync.params.visibilityId?: number`，非负安全整数。宿主每次发送显示/隐藏请求递增，前端在对应提交及后续布局同步原样回传；宿主在更改区域/交互/阶段之前拒绝过期编号。初始预加载编号 0。本版双方必须发送/回传；可选只用于兼容旧客户端。用来拒绝同时排队的旧 expanded=true/false，不能只过滤 false。
- `window.visibility {visible:false}` 是退出请求。前端保留浮岛 DOM 和 `expanded:true` 播放 300ms 退出过渡；结束才报告 `expanded:false`，原生此时隐藏 HWND。Esc/收起按钮也在过渡结束后提交 collapsed。宿主退出等待有有界超时兜底，重入取消退出；等待新展开时忽略旧 collapsed 报告，不能先清空命中区域。系统减弱动态效果或软件减弱动效启用时直接完成。
- 每屏独立热区，共享一个浮岛 WebView。移动采用物理桌面坐标（允许负坐标），每屏 DPI 换算不可用于改变物理原点。原生独占自动收起计时，浏览器演示可自行计时。全屏避让仅针对全屏应用所在屏。


## 第四轮：真实目录浏览与稳定滑动（2026-09-19）

具体复现和实现边界在《第四轮目录与成组修复计划.md》中先行记录。protocol=1、schemaVersion=1 与既有方法不变。

| 方法 | params | result |
|---|---|---|
| folder.list | `{projectId,itemId,folderId?}` | `{folderId,name,entries:[{id,name,kind}],parentId,truncated}` |
| folder.open | `{projectId,itemId,entryId}` | `{accepted}` |

- 首次不传 folderId，从最新保存的 folder 类型入口解析根目录。后续 folderId / entryId 仅接受宿主签发的不透明 ID，不接受 JSON 路径；当前 folderId 也能用于打开当前目录。
- 每次只读取当前一级，最多枚举 201 项、返回前 200 项并标记 truncated；限定页内目录优先、名称自然排序。不保证超大目录全部内容的全局排序，也不递归扫描。
- ID 绑定 clientId、projectId、itemId 和当时根路径，5 分钟过期；打开前重验路径、根入口、存在性。返回上层仅到绑定根目录。目录链接/联接点不跟随；目录内 .lnk/.url 暂不隐式启动，可以把目标单独保存为快捷入口。
- 全局最多两个后台目录任务，4 秒响应超时，超时任务实际结束前仍占槽位。忙、过期、无权限和不存在均返回可见错误，不伪造为空目录。浏览不保存、不启动；启动请求按 clientId/requestId 去重。
- 单文件夹长按展示真实内容；多入口组合展示全部成员（包含默认入口），其中目录成员可继续浏览。移动到条目松手才打开，移出取消。前端目录打开只传上述 ID。
- 主面板纵向入场 360ms / 退场 300ms，使用单个 transform/opacity 合成动画，不缩放或弹跳；中途反向从当前帧接续。减弱动效为即时切换。
- window.sync 的 rects 使用抵消 wrapper translateY 后的静止坐标，并额外包含向屏幕顶边滑动的局部扫过区域；不按每动画帧发送桥接或 SetWindowRgn。初次入场等宿主 SyncDock 已应用区域/显示后回应 applied:true 再播放。可见性编号和退场完成才 collapsed 的规则继续生效。
- 右侧整理模式下，图标拖到图标上合并保存引用，目标默认入口/名称/顺序保留、源入口按路径去重追加；失败不能丢项。可拆分为独立图标。保存仍走原 app.saveState 的 expectedRevision，不更改真实文件。

- 慢目录 list/open 不占用窗口同步顺序队列；其余请求及 DPR/window.sync 保持先后顺序。原生关闭后忽略迟到响应。
- 前端主动 collapsed 时，若鼠标物理坐标仍在热区，抑制该处合成 hover，直到真实离开再进入；不以单独 WM_MOUSELEAVE 判断，不增加常驻轮询。点击、OLE 拖入和托盘/快捷键可主动解除；原生 Closing 自动收起不触发此抑制。

## 第五轮：清晰推拉、固定格子与原生软件图标（2026-09-19）

本节覆盖第三/四轮历史动效参数与交互保持条件，其他既有语义不变。先行复现场景见《第五轮动效与图标计划.md》，最终验证见《第五轮修复报告.md》。protocol=1、schemaVersion=1及两个宿主事件不变。

| 方法 | params | result |
|---|---|---|
| shell.getIcon | `{projectId,itemId,size?}` | `{dataUrl:string|null}` |

- size仅允许32/48/64/96，缺省64；只从当前已保存入口解析路径，不接受JSON路径或额外字段。入口不存在、删除或提取失败返回null；非法参数仍拒绝。结果仅允许PNG data URL，最多350000字符。
- Windows Shell使用IShellItemImageFactory的ICONONLY读取软件/快捷方式原图标，不启动、不修改目标、不把图像写入用户配置。提取在两个后台STA工作线程进行，排队上限128；4秒响应超时后实际任务继续占用工作槽位，不增生线程。HBITMAP与COM对象必须finally释放。
- 原生与前端缓存均有条目和字符预算（128项、600万字符），成功5分钟、失败5秒。原生结果绑定revision/project/item/path/size，入口变更后丢弃过时结果。前端收到本页成功保存结果或跨页有效app.stateChanged后刷新派生缓存，不轮询、不伪造新宿主事件；相同入口刷新时保留已显示品牌图像，路径改变则隔离旧图。
- shell.getIcon与folder.list/open独立于窗口消息顺序队列执行，慢图标不能阻塞DPR/window.sync。
- 主面板入场650ms、退出600ms，`cubic-bezier(.42,0,.58,1)`、完整纵向transform、opacity恒为1；不缩放、不弹跳。首次入场收到当前expanded确认后保留隐藏首帧再播放；反向从当前帧接续。只在动画存续期间使用合成层提示，常驻不播放动画。
- Luma内reducedMotion=true仍即时完成；本轮按用户要求由软件明确控制推拉动画，不改Windows系统设置。原生退出1400ms兜底，两处时限共用常量；正常仍必须等待当前visibilityId的collapsed才隐藏。

## 第六轮：复用已打开窗口与原生主题（2026-09-20）

用户要求已打开/最小化的目标优先恢复前置，避免重复启动。采用现有共同Shell出口，不新增方法或字段；protocol=1、ID校验和目录/搜索令牌边界均不变。

- 文件夹按规范化完整路径与Shell COM LocationURL匹配，忽略大小写但不按名称/窗口标题猜测；同名不同路径不混淆。软件.exe及无参数.lnk按完整可执行路径匹配。只读取已有快捷方式，不保存或改写它。

- Windows恢复/激活可能异步完成，只在本次用户操作中最多200ms确认恢复、100ms确认前置；没有常驻轮询，只调用一次SetForegroundWindow。窗口仍最小化时不能仅凭系统接受前置请求报告成功。
- 同目标启动保护15秒，仅在用户请求时清理和查找；期间目标还未出现时合并重复点击。此保护不等同于跨软件永久单实例保证，不常驻扫描窗口。现有同请求ID去重继续有效。

# 第十一轮补充：引用集合、最近项目和实际目录操作

## 自动启动、搜索和引用语义

- 根目录手动 `launch` 优先；自动脚本优先已有 test，其次具有明确 Tauri 元数据的 tauri dev，再 dev/start。未识别时不猜测执行，保留手动配置入口；`.lnk` 软件入口不作为代码目录识别。MOMO 根目录已有 `tauri` 脚本和 Tauri 配置，对应 `pnpm run tauri dev`。识别不运行，清单变化必须重新识别，禁止自动安装依赖。
- `search.query` 增加可选 `appAliases`（默认true）与 `fuzzyNames`（默认false）。AI/PS等只用于软件入口；文件/目录低强度模糊仅已保存入口。Windows 索引仍是有界词首/正文查询，不递归扫描、不承诺磁盘全量模糊匹配。
- 拖到图标中心合并引用，边缘插入排序；整理模式 X 移除引用，集合内可提取/拖出/拖入。目录文件拖到普通集合始终不调用实际写入；实际移动仅在明确的“移动到当前实际目录”落点或菜单后确认。外部文件拖入普通面板仍通过真实 File AdditionalObjects 导入引用，不将字符串路径当作文件来源。
- 顶栏1120px/屏幕可用宽度封顶，剩余入口横向滚动。右键拖动≥7px为滚动且不弹菜单，普通右键保留上下文菜单。子菜单右键纵向拖动。
- 分割按钮两侧及原图标均保留长按展开；布局变化后未再次移动，松手不误开新落点。已进入子菜单时父级保留；单击仍打开目标。软件使用“打开软件 / 最近”。
