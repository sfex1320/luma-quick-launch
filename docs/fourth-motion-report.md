# 第四轮浮岛动效修复记录

## 根因与改动

旧实现只移动 12px，展开 200ms、退出 180ms，`cubic-bezier(.22,1,.36,1)` 在起始段快速完成大部分位移。与此同时，动画的每一帧触发 `window.sync`，继而读取 WebView DPR 并重建 HWND 裁剪区域。

新增 `src/components/useDockMotion.ts`：完整浮岛从屏幕顶边外纵向滑入，展开 360ms、回收 300ms，曲线为 `cubic-bezier(.25,.1,.25,1)`；没有缩放、弹跳或越界回弹。位移按实际内容最底部计算，包含绝对定位的目录/更多面板，并在顶边外保留 16px 余量。此实现是重新设计的滑入滑出，不是“恢复弹簧”。

- 退出结束后才移除 DOM；取消的旧动画不会调用退出回调。
- 中途反向先读取当前计算样式，再取消旧动画，以该画面作为新动画起点。
- 原生首次挂载的进入动画停在第 0 帧，等同一次布局确认后由 `resumeEntrance()` 播放，避免窗口尚未显示时消耗进入动画。
- 应用和系统减弱动态效果使用 0ms，仍保留退出完成的 DOM/宿主握手。
- 仅在动画期间设置 `will-change`，没有动画逐帧 JavaScript、常驻轮询或空闲动画。
- `getDockTranslationY()` 提供当前纵向位移，供 Dock 的固定局部原生区域上报还原静止布局；Dock 已去除逐帧同步。每个移动面板的完整向上路径以局部矩形保留到 DOM 退出，覆盖宽目录面板及中途反向的两侧阴影。

## 检查证据

2026-09-19：新增控制器后 `npx tsc -b` 退出码 0。

2026-09-19：Dock 接入后，最终 `npx playwright test tests/motion.spec.ts --reporter=line` **4 passed**；`npx tsc -b` 退出码 0。覆盖屏外起点/布局确认、单调纵向位移且无缩放、退出 DOM 保留、中途反向、退出布局同步次数、减弱动态效果，以及 320px 主栏与 350px 堆叠在退出和反向时的完整阴影路径覆盖。

区域审查发现仅在退出时追加路径矩形，会在反向进入的第一帧丢失宽面板侧边区域；主任务已将固定路径保留改为整个 present 阶段。此覆盖仍仅在各面板局部横向宽度内，不覆盖整屏承载窗口。

手势审查向主任务报告两个独立边界：Esc 收起前应立即清除仍按住的启动计时；异步目录打开回调不应关闭用户随后切换到的新堆叠。相应修改归 Dock 整合方，本子任务未改 Dock。

以上是 Edge 浏览器模拟宿主的前端行为验证，不能替代真实 Windows 集成验证。本子任务未改原生文件、未发布或重启应用。
