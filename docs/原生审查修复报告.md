# 原生审查与修复记录

日期：2026-09-19。针对用户截图中的大面积灰色遮挡，对 GLM 交付的原生程序进行了复现、修复和真实进程复验。本报告优先于此前《内核验收结果》的完成判断。

## 确认的原因与修改

| 问题 | 原因与修复 |
|---|---|
| 待机仍出现整屏宽灰块 | 对 3840×960 物理像素的承载 HWND 启用了 DWM system backdrop；即使 HRGN 为空，DWM 仍绘制整窗背景。原进程中仅将属性 38 设为 NONE，灰块立即消失。现明确关闭该背景，并设置 WPF 合成背景透明。 |
| 面板偏移、被裁掉、部分图标无法点击 | 只使用显示 DPI 1.5，遗漏用户的 126% 系统文字缩放。实际 WebView devicePixelRatio=1.89。现随布局上报读取实际比例，统一转换区域与热区。无额外协议字段、无常驻比例轮询。 |
| 收起后再次唤出、首次启动不稳定 | 前端、窗口和 EdgeActivation 三套可见状态未同步，首次事件还可能早于页面加载。现等待首次布局，前端收起同步宿主；显示器重定位恢复也走完整唤出路径。 |
| 损坏文件覆盖用户配置 | 双损坏后仍把默认空状态当成功状态返回。现 getState/保存/启动均拒绝使用损坏状态，保留原文件，返回 IO_ERROR。 |
| 恢复备份后再也无法恢复 | 首次保存把坏主文件替换进唯一有效备份，或删除有效备份。现恢复后的首次原子保存保留有效备份。 |
| `{}` 被当成有效空配置 | DTO 默认值掩盖必需字段缺失。所有契约字段标注 JsonRequired；损坏主文件会正确进入备份恢复。 |
| 同一请求并发启动两次 | 只缓存已完成操作，未缓存进行中的请求。现使用每个请求 ID 的 Lazy 操作；不同 ID 不在全局锁内等待网络。 |
| 设置切换丢失编辑草稿 | 原生切换栏目会重新加载整个页面。现使用同页 history/popstate；保持编辑草稿及尚未落盘的修改。 |
| 管理窗反复开关后泄漏 | 关闭仅 Dispose WebView、未从路由移除。现 Detach；浮岛关闭也释放 WebView。 |
| 原生启动反馈看不到 | toast 位于 Dock 外，未纳入 HWND 裁剪。现包含其矩形，显示/消失时更新，无持续轮询。 |
| 参数和入口无效 | 已有实例现在区分 --settings 与 --show-dock；“独立预览”在原生环境唤出真实浮岛；热区暂停不再禁用托盘手动唤出。 |
| 交付文件可能不更新 | 发布前先测试，仅停止本交付路径的进程；复制 dist 的内容到目标目录，并校验 index.html 哈希，避免嵌套复制。 |

另外修正 CreateRoundRectRgn 半径/直径混用，以及 Win32 热区 DefWindowProc 的 Unicode 声明。前端视觉样式和长按规则未重设计。

## 最新验证

- `scripts/build-native.ps1`：生产前端构建、Release 内核测试、自包含 win-x64 发布通过。
- 内核 xUnit：74/74。新补的四个配置恢复测试在旧代码上全部失败；修复后通过。另有损坏状态桥接与并发去重回归。
- 前端单元测试：12/12；Edge 浏览器 E2E：8/8。
- `npm run test:native`：真实 `APP/native/Luma/Luma.exe` + 真实 WebView2 + Shell，共 12 个检查点通过。测试没有注入模拟桥接。
- 验证了首次唤出、原生区域/穿透、收起再唤出、草稿保留、宽度保存并跨窗同步、可见启动反馈、真实打开目录、长按滑选仅启动一次、滑出取消、已有实例参数、自动收起、独立预览。
- 实测：承载窗口 3840×960，默认面板可见区域 x=1315..2525，中心为 1920；实际比例 1.8899999857。透明外围 WindowFromPoint 返回下层进程。不能仅凭 RegionType 或浏览器截图声称完整原生验收。
- 真实 Shell 打开的测试目录另外经 Windows Shell 窗口列表核实存在。手势自动化由 WebView2 的 CDP 注入；并不等于已验证所有实体鼠标、触控笔输入设备。

机器结果保存于 `docs/native-regression.json`。测试目录为独立的 `%TEMP%/luma-native-smoke-*`；通过 `LUMA_DATA_DIRECTORY` 隔离配置、WebView 用户目录和单实例信号，不替换 `%LOCALAPPDATA%/Luma` 的用户文件。

## 明确的限制

1. **真实桌面背景 Acrylic 暂不启用。** 当前保留 CSS 玻璃层次和半透明外观；CSS 不能模糊窗口外的桌面。后续要使用受限范围的原生合成实现，不能把 system backdrop 加回全宽承载 HWND。
2. 本轮未改变用户显示设置。150% 显示缩放叠加 126% 文字缩放已实测；其他 DPI、热拔插、独占全屏和不同输入设备尚未逐项验收。
3. 本轮没有重新测量进程树内存/GPU/DWM；旧性能报告不是当前修复版本的新证据，也不代表达到低内存目标。
4. 项目与资源管理器已打开窗口/标签的关联、开机启动仍未实现。特殊名称路径中的命令关键字误拒绝是后续边界改进项。

## 使用与后续约束

双击根目录 `启动Luma.cmd` 打开管理窗；程序位于 `APP/native/Luma/Luma.exe`。部署时保留整个 Luma 目录。

后续代理先读此报告和协议；不得恢复整窗 Acrylic、假定 CSS px=WPF DIP、让配置错误退回空数据、或把宿主模拟测试写成真实 Windows 成功。

参考：[Microsoft DWM 背景类型](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwm_systembackdrop_type)说明背景作用于 entire window bounds；[WebView2 RasterizationScale](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.core.corewebview2controller.rasterizationscale)说明其包含显示 DPI 与系统文字缩放。
