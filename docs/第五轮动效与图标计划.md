# 第五轮：可见滑动、固定格子、原生图标

用户已明确要求在当前软件上直接实施，本轮继续执行，不重复要求设计确认。Michael 的具体产品身份尚不明确；按用户给出的可观察行为实现缓慢向下推出/向上回收，不宣称复刻某产品。

- 动效先实测宿主动画/系统减弱动效/裁剪。目标约650ms推出、600ms回收，完整纵向位移，以可见滑动为主，避免透明度过早消失；保持局部固定命中区域和visibilityId，原生兜底时限留足动画+调度时间。按用户明确要求由软件内“减少动态效果”开关控制，不修改Windows系统设置。
- 三个工具按钮固定在主栏右侧独立组，左边入口区占剩余空间；容量计算预留右侧宽度。
- 二级目录与组合成员全部采用固定尺寸格子（88×94 CSS px，随可用宽度调整列数而不拉伸格子），长名称截断并完整title，独立可滚动内容区；目录格子的浏览箭头与打开动作分离。
- “打开当前目录”参与同一长按滑选 hit target：按住根图标或成员，移至底部动作松手后以当前folderId打开；移出不打开；键盘click仍可用。
- 原生软件图标最小增补 `shell.getIcon`，params `{projectId,itemId,size?:number}`（size 32/48/64/96，缺省64），result `{dataUrl:string|null}`，仅PNG data URL、最多350000字符。不接收任意路径，不保存图标到配置，不启动软件；按最新保存入口取路径，支持Windows .exe/.lnk自身图标（含自定义图标/快捷方式）；有界缓存、后台提取并释放HICON/HBITMAP/COM对象，失败回退现有图标。协议仍为1。
- 前端 ItemIcon/GroupIcon 可传 projectId/itemId 获得原始图标，保留软件可识别内容，外加圆角玻璃底座/浅高光/阴影；目录内容临时token项保持现有文件类型图标。

分工：root拥有Dock、FolderBrowser、grid/toolbars CSS、布局及整体验证/文档；motion子任务拥有useDockMotion与motion测试、原生动效必要修改；icon子任务拥有contracts/bridge、ItemIcon/GroupIcon/新增icon组件、原生图标服务及BridgeRouter路由和图标测试。不同测试进程不能共用Playwright输出目录，真实Windows UI测试由root串行执行。
