# 第十五轮交互与层级修复报告

2026-09-22 · 版本 **0.3.5** · 交付源码 `58b4551a1834b5fb4ee91673b224cd50b315975e`

## 用户反馈与根因

本轮处理用户三张截图反馈，另附排查报告（只报告、未动手项见文末）。

### 图片1：三级菜单与二级菜单错位

- 现象：进入子目录后，子列的"返回 + 文件夹名"标题行比父列内容低约一行，两列文件夹网格横向错位。
- 根因 1（结构）：第十四轮"根重复行移除"后，根列（level 0）不再渲染 `.folder-browser-path` 标题行（`FolderBrowser.tsx` 的 `index > 0` 守卫），子列保留标题行，网格起点因此不一致。
- 根因 2（高度）：标题行内 `.icon-button` 为 30×30px，子列标题行实际 48px 高，而纯文字标题行约 34px——即使顶部对齐，网格仍差 14px（实机复现值）。
- 附带发现：截图1 左列顶部的"快捷启动项"实为磨砂玻璃透出的后方 Kimi 侧栏文字（该列当时并无标题行，有旧断言为证）。透明材质会把背景窗口文字误读成 UI 元素。

### 图片2：搜索窗被一/二/三级菜单遮挡

- 根因：浮岛 `DockWindow.Topmost = true`（产品语义即"面板显示在普通窗口上方"），而 `SearchWindow`/`SettingsWindow` 是普通窗口，永远无法盖过浮岛，覆盖区域既看不见也点不到。

### 图片3：快捷键设置位置

- 原状：`ShortcutSettings` 嵌在"设置与备份"页内。用户要求挪到其下方、作为系统组独立模块从主导航进入。

## 修复内容

- `src/components/FolderBrowser.tsx`：所有层级渲染统一标题行；返回按钮仍只在 ≥1 层列内出现（根列返回分组保留在面板顶栏，避免双按钮重复）。
- `src/components/GroupEntryMenu.tsx` + `src/components/Dock.tsx`：组列仅在旁侧存在目录/最近项目列时（`withTitle`）补同高标题行（Layers3 + 项目名）；组列单独存在时不加，保留第十四轮去重复行的意图。
- `src/components/folder-browser.css`：`.folder-browser-path` 固定 34px 高（`height:34px;padding:0 5px`），内嵌 `.icon-button` 收到 22px——所有列标题严格同高，网格天然横向对齐。
- `native/Luma.Host/Windows/SearchWindow.cs`、`SettingsWindow.cs`：`Topmost = true`，Luma 自有伴随窗口浮在置顶浮岛之上；不新增抢前台逻辑，Activate 行为不变。
- `src/App.tsx`：新增 `shortcuts` 页（系统组导航位于"设置与备份"下方，Keyboard 图标），`ShortcutSettings` 迁入；`section=shortcuts` 初始映射与 popstate 深链同步支持；帮助弹窗文案更新为"在系统 · 快捷键页添加快捷键"。
- `native/Luma.Host/Windows/SettingsWindow.cs`：`SectionUrl` 白名单加入 `shortcuts`。
- 版本 0.3.4 → 0.3.5（`package.json`、`Luma.Host.csproj`）。
- 测试夹具更新（不改变生产二进制语义之外的断言）：`tests/fourteenth-directory-layout.spec.ts` 根列标题行断言改为存在且显示目录名，并新增**两列标题 y 差、网格 y 差均 < 1px** 的对齐断言；`tests/thirteenth-hotkeys*.spec.ts` 导航目标改"快捷键"；`native/tests/fourteenth-features-smoke.mjs` 根列标题断言同步更新。
