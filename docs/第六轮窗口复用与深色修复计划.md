# 第六轮：窗口复用与深色界面修复

2026-09-20。用户已明确授权直接修复，沿用现有前端和宿主，不重复询问已确定的设计。

## 规则与边界

- 从快捷面板打开文件夹、项目入口或软件时优先查找对应的已打开窗口；最小化则恢复，再切到前台。这里“最上方”解释为激活前置，不永久设Topmost。
- 文件夹按规范化完整路径匹配Windows Shell窗口，禁止用标题猜测。软件按解析后的快捷方式/可执行身份匹配，不按显示名称猜测；保留快捷方式参数语义，不能误激活同软件的不同目标。无法安全识别时有明确退回边界。
- 查找仅在用户启动动作时发生，有界执行；不常驻遍历窗口，不全盘扫描。复用成功不得再调用Shell启动，连续点击需防止启动期间重复。
- 沿用shell.openItem、folder.open和search.open及原有ID/令牌校验；不让前端提交任意路径，不改protocol=1。
- 深色模式覆盖原生设置/搜索标题栏、WebView背景/控件、滑块和滚动条；切换浅色同步恢复。保留浮岛透明原生背景规则。
- 外观页自动收起/减少动态效果/说明/撤销统一内边距，与上方材质/主题内容对齐；窄视口不溢出。

## 执行与分工

1. 窗口复用子任务：原生启动服务与新建复用服务、针对性测试、可串行运行的真实Windows验证脚本。
2. 原生主题子任务：设置/搜索窗口标题栏及主题状态同步，不接触启动服务或前端CSS。
3. 主任务：前端CSS/布局、测试、协议及交接文档；最终统一构建，串行真实Windows验收并恢复用户应用。
4. 独立代码复审后修复有效发现；所有完成结论引用最新验证，不以模拟替代真实宿主成功。

Ruling：新规则应用于共同启动出口，因此保存入口、目录令牌及搜索结果保持一致；窗口复用不更改用户文件。成本与边界在报告中记录，不承诺无法识别的第三方多实例/自定义窗口都可完美关联。
