# 第二十三轮：退出诊断、菜单规范与真实文件拖放

用户确认“关闭”是软件自行退出。旧实例 2026-09-24 18:41:13 后停止写日志，19:04:12 新实例启动，未见正常退出记录；当前证据不足以断言崩溃根因。不接管鼠标、不抢前台、不恢复长测，后台验证后直接更新 APP/Luma。

## 行为和接口

- 菜单标题固定单行 12px/18px，入口计数 11px/18px，不压缩为竖排；磁贴名称单行省略，title 保留全名。筛选框优先收缩，动作按钮保持完整。规则写入前端设计规范并覆盖窄视口测试。
- 软件能力只由宿主解析已保存软件 ID 判断。新增 `shell.getAppCapabilities({projectId,itemId}) → {recentSupported:boolean}`；没有专属最近来源时仅显示“打开软件”，使用软件图标。能力未知时不展示最近，组导航不受影响。
- 普通模式真实文件拖放：默认/Ctrl 复制，Shift 移动，Alt 创建 .lnk。Alt 优先于 Shift，Shift 优先于 Ctrl。落在真实子目录磁贴上以该目录为目标，落在目录空白以该列为目标，落在主栏文件夹以其根为目标；组有多个目录时列出选择，不猜目标。
- 编辑模式仅添加、移动或合并快捷引用，不触碰源文件。普通模式内部入口拖到文件夹也遵循真实文件规则。
- 提交前显示动作、来源数量和目标目录确认，沿用已有目录操作确认规则。保留最终结果，不以普通桥接八秒超时假报失败。同名不覆盖，拒绝重解析目标、自包含、跨卷移动和超过有界数量/深度的目录树。
- 新增 `folder.transfer`：`{operation:'copy'|'move'|'link',targetProject,targetItem,targetFolderId,sourceProject?,sourceItem?,sourceEntryId?}`。外部源仅来自 WebView AdditionalObjects 的真实文件对象；内部源仅来自保存 ID 或当前目录令牌。二者互斥，不接收 JSON 路径。返回现有 MutationSchema；protocol 仍为 1。

## 实现与验证顺序

1. 补生命周期异常/退出原因诊断，定位没有新输入时的唤出路径；修复有证据的重排或合成消息入口，保留单击/OLE/正常重入。
2. 原生文件服务复用 FolderMutationService 的路径句柄固定、目标令牌、并发上限与提交语义，临时目录测试三种操作及拒绝边界。
3. 桥接严格字段校验、能力查询；前端实现拖放确认和目标选择、目录刷新，编辑与普通模式分别回归。
4. 字号和单行布局回归、无最近软件能力回归；运行前端、原生单测与相关 Edge 测试。
5. 版本与打包同步、后台最终 EXE 检查，保护配置和桌面快捷方式并替换 APP；不能执行的前台实机验收明确记录，不冒用历史测试。
