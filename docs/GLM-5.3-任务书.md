## 直接执行的指令

你接手的是已经完成首版前端的 Windows 快捷启动器。先读根目录 AGENTS.md、src/contracts.ts、docs/内核接口协议.md，再按本任务书从 K1 顺序执行。不要重新做需求访谈，不要比较一轮 UI 框架，不要重写 React 界面，不要更换视觉或交互。每完成一个任务运行对应验证，发现错误自行定位修复。

用户已经确定：局部顶边浮岛、圆角强磨砂、水晶项目文件夹堆叠、长按展开后滑选松手打开、宽高和图标可调。前端由 Codex 负责；你负责原生宿主、Shell、配置存储、屏幕热区、材质、托盘、系统对话框和最终打包。

## 固定技术边界

- Windows 11 x64，C# + .NET 10 LTS + WPF 宿主 + Microsoft.Web.WebView2。WPF 只做系统承载，不重画业务 UI。
- 前端 `dist/` 加载进 WebView2，桥接实现 `src/contracts.ts` 中协议 v1 的全部方法与两个事件，包含协议文末的兼容增补。
- 内核放 native/，所有内核自动测试放 native/tests/；部署脚本放 scripts/，不得覆盖前端脚本。
- 不引入 Electron、数据库服务器、账号系统、第三方完整桌面外壳、AI 分类、后台全盘扫描。
- 2026-09-19 检查本机只有 .NET SDK 8.0.403/9.0.306。内核实施前检查并准备 .NET 10 SDK；不能误报此依赖已满足。构建完成后固定 SDK 版本在 native/global.json，固定 NuGet 依赖。
- 普通用户权限启动；只有实际系统安装行为需要时才触发相应系统权限。

## 预期目录与职责

```text
native/
  Luma.sln
  global.json
  Luma.Host/
    Luma.Host.csproj
    App.xaml / App.xaml.cs           单实例、生命周期、托盘

    Windows/SettingsWindow.cs       管理窗与系统对话框归属
    Bridge/BridgeRouter.cs          来源校验、协议、请求分发
    Bridge/Contracts.cs             对齐 TypeScript/JSON Schema 的 DTO
    Services/StateStore.cs          版本控制、原子保存与备份

    Services/FolderPicker.cs        选择文件夹并返回 path/name 或 null
    Services/EdgeActivation.cs      屏幕热区、延迟、全屏避让
    Services/MonitorService.cs      DPI、显示器改变与主屏回退
```

文件名允许为适应实际 WPF 工程的小范围调整，但职责不能合并成一个上千行窗口类。宿主原生透明命中和材质裁剪可能需要辅助 HWND；只在上述 Windows/Services 范围内实现并记录，不能以此改前端。

## 第三轮交互约束

回收必须等待前端退出结束的 collapsed 确认；不能在发送 visibility=false 时立即 Hide，也不能以命中矩形数量判断用户正在操作。保留可选 window.sync.interacting、800ms 退出确认兜底及重入取消机制。每屏原生热区必须注册 OLE 文件拖放目标；普通 WM_MOUSEMOVE 悬停和 CDP 拖放测试不能替代真实 DoDragDrop 证据。设置页拖放仅保存入口，不执行文件或移动目录。后续修订以《第三轮交互修复报告》与对应测试为基线。
