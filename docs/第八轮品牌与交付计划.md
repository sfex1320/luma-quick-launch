# 第八轮：品牌、兼容与交付完善

依据：用户要求纯图形无字母 Logo，先品牌再兼容，再按项目数自动扩宽，并处理上一轮列出的交付缺口。

## 设计与执行顺序

1. 品牌：悬浮叠片、水晶玻璃、纯绿色系（用户追加要求，去掉蓝色）；无文字或字母。统一网页、设置页、EXE、托盘、快捷方式与安装器图标，提供源资产和多尺寸 ICO。
2. 兼容：明确支持目标和实测矩阵；补 WebView2 依赖检测与安装路径、便携版缺失提示。不虚报其他 Windows/ARM 机器的实测。维持普通用户运行。
3. 宽度：当前保存宽度作为初始宽度；只计算置顶顶层入口，按实际图标尺寸扩展，最多 1120 且不越过当前屏幕；减少入口时缩回但不小于初始值。减少动态模式立即响应。保持滑入 650ms/滑出 600ms、右侧操作区与长按协议。
4. 可靠性：检查 WebView 崩溃恢复、配置备份恢复、资源占用；增加隔离的持续运行/故障实测，覆盖宿主与子进程，避免动用户配置。
5. 发布：明确版本升级/回退、签名验证流程及自动化入口。真实受信任代码签名需要发行主体和有效证书，不能伪造或使用自签名冒充；若缺少则明确未签名。生成新版便携 ZIP/安装 EXE，执行完整验证。

## 验证和声明边界

- 前端单测/E2E、原生单测、真实 native/system/lifecycle/installer 回归。
- 图标检查多尺寸、透明度与 EXE 资源；布局检查增减、上限、窄屏与 reduced motion。
- 将“已有实现”“当前机器实测”“待外部设备/证书”分开记录，不把测试版声明为所有 Windows 均已验证。
