# 第五轮修复报告：推拉动效、固定菜单与原生图标

2026-09-19，Windows 11 / WebView2，针对用户本轮要求直接修改现有项目。交付路径为 `APP/native/Luma/Luma.exe`；没有新建另一套界面或变更用户快捷项。

## 结果与原因

### 1. 缓慢向下推出、向上收回

旧版不是没有动画，而是360ms入场/300ms退场叠加淡入淡出：真实WebView退出约175ms时底边仅剩0.56 CSS px，透明度约0.126，后半段几乎看不见。Windows的MinAnimate注册表为0，但该WebView实际reduced-motion媒体查询为false，不能把本机问题归因于系统强制关闭动画。

现在推出650ms、收回600ms，使用对称缓入缓出，透明度全程1，以完整纵向移动呈现推拉。没有缩放或反复弹跳。中途反向从当前画面接续；首次入场等原生窗口确认可绘制后保留隐藏首帧再播放。退出保留DOM，到动画完成并回传当前visibilityId后才隐藏HWND；原生兜底同步延长到1400ms。保持固定扫过区域，不逐帧调用window.sync/SetWindowRgn。

真实交付程序采集到退出37帧、入场43帧。退出400.08ms时底边仍在屏幕内14.57px，opacity=1；600ms时完整移出到-16px。入场由-131.989px移动到0，时长650ms。原始逐帧记录：[真实动效JSON](fifth-native-motion-after.json)。这项检查通过真实WebView键盘Escape与原生单实例唤出信号触发，不是模拟桥接；物理悬停另行验证。

软件内“减少动态效果”仍能即时切换；此次不修改Windows系统设置。“Michael”未提供具体产品或视频，按明确的缓慢下推/上收要求实现，不宣称逐帧复刻。

### 2. 固定右侧工具与二级格子

- 搜索、编辑、设置成为最右侧固定126px工具组。左侧快捷项使用剩余空间；布局容量为工具组与间距预留136px，窄栏溢出进“更多”。
- 二级目录、文件和组合成员统一88×94 CSS px格子，列数随可用宽度变化，格子不拉伸。菜单常规宽416px；长名称两行截断，悬停可查看完整名称。
- 内容多时只滚动格子区域；按实际视口和主栏高度限制菜单高度，底部操作保留可见。测试覆盖320/640/1000px主栏，以及500px短视口、160px主栏和60项目录。

### 3. 长按滑向“打开当前目录”松手打开

该按钮接入与文件条目相同的长按滑选链路：按住根图标展开，滑到按钮高亮后松手，使用宿主当前目录令牌打开；先移出再松手不启动。键盘激活保留。组合的默认入口采用同样行为。

已在真实交付宿主上验证：当前目录令牌经Windows Shell打开临时测试目录，并关闭该测试窗口；没有打开用户的PPTX。用户“电梯贴”真实一级内容读取正确：`2张电梯延展画面`、`电梯门原文件`、`20260907综合楼电梯门贴膜需求.pptx`。成组/拆分仍仅更改快捷引用、按CAS保存，不移动真实文件。

空闲二级菜单不再永久锁住浮岛：鼠标移开允许回收，按住滑选、整理拖动、导入等待和键盘操作期间继续保持展开。

### 4. 软件自身图标与玻璃风格

增加协议v1兼容方法shell.getIcon，只接收已保存的projectId/itemId和可选尺寸，不接收路径。Windows Shell读取.exe/.lnk自身图标，包含快捷方式自定义图标；前端保留品牌图像，外加圆角玻璃底座、轻高光和阴影。失败回退通用图标，不显示破图。

两个后台STA工作线程、有界队列与缓存、4秒响应超时、显式释放图像和COM资源；慢图标任务不阻塞窗口布局。保存或跨页状态更新后刷新缓存，同一入口刷新期间保留已显示图像，避免图标闪回占位符；没有定时轮询。

真实Shell已成功读取MOMO智能画布、Photoshop 2026快捷方式的96×96 PNG；MOMO还通过最终真实WebView显示验证。Photoshop验证的是提取与PNG解码，没有为测试把它添加进用户配置或启动软件。细节见[图标实施记录](fifth-icons-report.md)。
